# Install the Arcade agent plugin

This guide is for agent developers who want to use Arcade in their own coding agent or desktop client. Install the plugin, sign in, and run a task across your apps without creating API keys or configuring a gateway.

The plugin bundles a connection to Arcade's hosted MCP gateway with two skills, three commands, and the `arcade-operator` subagent. The gateway provides tools for email, calendar, chat, issues, docs, and other apps. The skills and other components help your agent choose and use those tools. Each client loads the components it supports, as shown in the [support table](#what-you-get-in-each-agent).

<GuideOverview>
<GuideOverview.Outcomes>

Install the Arcade agent plugin in your agent and run your first task against a connected app.

</GuideOverview.Outcomes>

<GuideOverview.Prerequisites>

- A supported client: Cursor, Claude Code, VS Code, GitHub Copilot CLI, Codex, or Claude Desktop
- An <SignupLink linkLocation="docs:agent-plugin-install">Arcade account</SignupLink>
- For Claude Code, Claude Cowork, Cursor CLI, and GitHub Copilot CLI: [Node.js](https://nodejs.org/) on the PATH of the host that launches their routing hooks. Those hooks run `node`. Cursor IDE and Cloud Agents, VS Code, Codex, and Claude Desktop Chat do not need Node.js.

</GuideOverview.Prerequisites>

<Callout type="info">
  The cross-client `npx plugins add` command does not finish every client
  install. Use the client-native steps below so the gateway and every supported
  plugin component load together. The install commands below use the plugin
  repository and are not pinned to a release.

**Local installation**

For an individual plan, or a Teams or Enterprise plan with **Allow Local Plugin Imports** enabled:

1. Clone the plugin into Cursor's local plugin directory:

   ```bash
   git clone https://github.com/{{ARCADE_PLUGIN_REPO}} ~/.cursor/plugins/local/arcade-plugin
   ```

2. Run **Developer: Reload Window**.
3. Open **Customize** and confirm the two Arcade skills, `arcade-operator`, rule, and MCP server are present.

Keep the clone inside `~/.cursor/plugins/local/`. Cursor ignores symlinks to folders outside that directory.

To update the plugin later:

1. Run `git pull` in `~/.cursor/plugins/local/arcade-plugin`.
2. Run **Developer: Reload Window**.

**Team marketplace alternative**

Enterprise turns **Allow Local Plugin Imports** off by default. When it is off, Cursor ignores `~/.cursor/plugins/local`. Use a team marketplace:

1. An admin opens **Dashboard → Plugins & MCPs → Team Marketplaces → Add Marketplace → Import from Repo** and pastes `https://github.com/{{ARCADE_PLUGIN_REPO}}`.
2. Each person opens **Customize**, finds **Arcade**, and selects **Install**.

## Sign in

Arcade separates [gateway sign-in from app authorization](/learn/server-level-vs-tool-level-auth):

1. **Into the gateway.** Your client asks you to sign in when it first connects. Sign in to Arcade in the browser so your client can connect to the gateway.
2. **Into each app.** When a task needs an app, your agent gives you a browser sign-in link for the required permissions. After approval, Arcade stores the authorization. You may need to reconnect if the connection expires or a later task needs additional permissions.

After you finish in the browser, return to your agent and continue the original task. Arcade does not resume it for you.

You never give your agent an API key or a password for either layer. To check or manage connections, ask your agent to "Check my Arcade connection," "Show my connected apps," or "Connect Google." You can connect an app before you need it. Clients that support Arcade commands also provide the shortcuts listed below.

Arcade uses the app connections authorized for your signed-in identity. Authorize only the accounts you intend the agent to use.

### Privacy

The released plugin turns client-side usage telemetry off in code. No environment setting turns collection on. Requests you make through Arcade still go to its hosted gateway and the apps you authorize. See [Arcade's privacy policy](https://www.arcade.dev/privacy-policy).

## What you get in each agent

Every install connects to the same Arcade gateway and gets the same tools. What differs is how much of the rest of the plugin each agent can load.

### Commands

Claude Code and Cowork namespace the commands as `/arcade:arcade-status`, `/arcade:arcade-connect`, and `/arcade:arcade-apps`.

#### `/arcade-status`

Reports whether the gateway is reachable, whether you have signed in, and which apps you have authorized.

#### `/arcade-connect <app>`

Authorizes an app on demand, so you are not interrupted mid-task.

#### `/arcade-apps`

Lists the apps you have connected and lets you disconnect one.

### Skills

Skills are instructions your agent reads when relevant to a request:

- `try-arcade` guides tasks across your connected apps, such as replying to a thread or checking your calendar.
- `scale-arcade` guides decisions about using a workflow with a team, including gateway setup, tool selection, and end-user identity.

### Subagent

The `arcade-operator` subagent runs an app task in its own context and reports the result. It keeps tool searches and intermediate results out of your main conversation.

### Rule and hooks

The rule and hooks tell your agent when to use Arcade for app tasks.

The [Agent Plugins](https://agent-plugins.org) 1.0 specification makes only skills and MCP servers portable. Commands, subagents, hooks, and editor rules require client-specific support.

### How Arcade chooses a connection

Arcade prefers the plugin's gateway. If it cannot complete a task for a reason other than sign-in or permission denial, your agent may use another already-authorized connection within the task you approved. It checks the intended app account before using another Arcade gateway. Sign-in and permission failures require your attention. The agent does not switch connections to get around them. The plugin instructs your agent to confirm the action and destination before changing something in an app.

`arcade-operator` falls back only to another authorized Arcade gateway. Fallback to any other tool belongs to the parent agent.

## Try it

- "Send a summary of tomorrow's calendar events to me on Slack."
- "Read my Granola notes from last week, check them against Linear, and file anything I promised that is not a ticket yet. Wait for me before creating anything."
- "Find unread mail that needs a reply. Look the sender up in HubSpot if you can, draft a response, and Slack me the draft before sending."
- "Pull my open GitHub pull requests, my Linear issues, and tomorrow's calendar. Write a standup update and send it to me on Slack."
- "Search my Drive and Notion for the product spec my team uses, then drop a one-paragraph summary in Slack."

Or ask "What can Arcade do?" and pick a workflow from the answer.
