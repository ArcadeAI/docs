# Install the Arcade agent plugin

This guide is for agent developers installing Arcade in their own coding agent or desktop client. Personal installs use Arcade's hosted gateway without creating API keys or configuring a gateway.

<GuideOverview>
<GuideOverview.Outcomes>

Install the Arcade agent plugin in a supported client and connect to its hosted gateway.

</GuideOverview.Outcomes>

<GuideOverview.Prerequisites>

- A [supported client](/get-started/agent-plugin/whats-included#client-support): Cursor, Claude Code, VS Code, GitHub Copilot CLI, Codex, or Claude Desktop
- An <SignupLink linkLocation="docs:agent-plugin-install">Arcade account</SignupLink>
- For Claude Code, Claude Cowork, Cursor CLI, and GitHub Copilot CLI: [Node.js](https://nodejs.org/) on the PATH of the host that launches their routing hooks. Those hooks run `node`. Cursor IDE and Cloud Agents, VS Code, Codex, and Claude Desktop Chat do not need Node.js.

</GuideOverview.Prerequisites>

</GuideOverview>

## Install

<Callout type="info">
  The cross-client `npx plugins add` command does not finish every client
  install. Use the client-native steps below so the gateway and every supported
  plugin component load together. The install commands below use the plugin
  repository and are not pinned to a release.
</Callout>

**Local installation**

For an individual plan, or a Teams or Enterprise plan with **Allow Local Plugin Imports** enabled:

1. Clone the plugin into Cursor's local plugin directory:

   ```bash
   git clone https://github.com/{{ARCADE_PLUGIN_REPO}} ~/.cursor/plugins/local/arcade-plugin
   ```

2. Run **Developer: Reload Window**.
3. Open **Customize** and confirm the two Arcade skills, `arcade-operator`, rule, and MCP server are present.
4. Run `/try-arcade` to start.

Keep the clone inside `~/.cursor/plugins/local/`. Cursor ignores symlinks to folders outside that directory.

To update the plugin later:

1. Run `git pull` in `~/.cursor/plugins/local/arcade-plugin`.
2. Run **Developer: Reload Window**.

**Team marketplace alternative**

Enterprise turns **Allow Local Plugin Imports** off by default. When it is off, Cursor ignores `~/.cursor/plugins/local`. Use a team marketplace:

1. An admin opens **Dashboard → Plugins & MCPs → Team Marketplaces → Add Marketplace → Import from Repo** and pastes `https://github.com/{{ARCADE_PLUGIN_REPO}}`.
2. Each person opens **Customize**, finds **Arcade**, and selects **Install**.

## Install the ChatGPT ZIP

This path requires a ChatGPT account with plugin upload access. For a managed workspace, an eligible owner or admin uploads the plugin; members install it from their workspace's plugin directory.

1. Open [Arcade's official plugin releases](https://github.com/ArcadeAI/arcade-plugin/releases) in your browser.
2. Expand **Assets** on a release that includes the ChatGPT plugin and download `arcade-chatgpt-{VERSION}.zip`. Do not use GitHub's **Source code (zip)** download. If the ChatGPT ZIP is absent, that release does not include it.
3. Keep the file compressed. On iPhone, Safari downloads appear in **Files → Browse → iCloud Drive → Downloads**, unless you chose another download location. On Android, find the file in Chrome's **Downloads** or your Files app.
4. Open [ChatGPT on the web](https://chatgpt.com) in the account and workspace where you want to install Arcade. Use the plugin upload option available to your account and select the downloaded ZIP. For eligible workspace owners and admins, the path is **Admin console → your workspace → Plugins → Add → Upload plugin**.
5. Select **Install plugin** if prompted, then connect Arcade and sign in when prompted.

If you don't see an upload option, check your account's access or ask your workspace admin. Uploading a ZIP to an ordinary chat does not install it. This installation flow is separate from submitting a plugin for public publication.

**Using a phone:** OpenAI documents plugin-directory installation in the mobile apps, but does not document ZIP upload in those apps or guarantee it in a mobile browser. Use ChatGPT web on a computer if the upload control is unavailable on your phone. After a workspace admin makes Arcade available, install it from that workspace's plugin directory in the mobile app.

See [OpenAI's plugin installation guide](https://help.openai.com/en/articles/20001256-plugins-in-chatgpt), [Apple's download instructions](https://support.apple.com/en-us/102440), and [Chrome's Android download instructions](https://support.google.com/chrome/answer/95759?co=GENIE.Platform%3DAndroid&hl=en-GB).

## Sign in

Arcade separates [gateway sign-in from app authorization](/learn/server-level-vs-tool-level-auth):

1. **Into the gateway.** Your client asks you to sign in when it first connects. Sign in to Arcade in the browser so your client can connect to the gateway.
2. **Into each app.** When a task needs an app, your agent gives you a browser sign-in link for the required permissions. After approval, Arcade stores the authorization. You may need to reconnect if the connection expires or a later task needs additional permissions.

After you finish in the browser, return to your agent and continue the original task. Arcade does not resume it for you.

You never give your agent an API key or a password for either layer. To check or manage connections, ask your agent to "Check my Arcade connection," "Show my connected apps," or "Connect Google." You can connect an app before you need it. Clients that support Arcade commands also provide [command shortcuts](/get-started/agent-plugin/whats-included#commands).

Arcade uses the app connections authorized for your signed-in identity. Authorize only the accounts you intend the agent to use.
